# Papo 0.25.1 发布说明

- 基线：Minecraft 1.21.11 / Paper 上游（分支 ver/1.21.11）
- 产物：`paper-server/build/libs/Papo-1.21.11-0.25.1.jar`
- 红线保持：行为等价、API 零变更、游戏版本红线 1.21.11 不变
- 性质：稳定性审计修复（非新增优化），仅针对不可信/损坏磁盘输入的内存健壮性

## 背景：网络服务稳定性 + 不可信输入审计

对 0.25.0 全部 202 个 feature 补丁做正确性/稳定性/安全性审计（人工逐补丁核对 + 三路子代理穷举扫描：对象复用重入/并发、事件门控可观察行为、数据持久化完整性）。

**审计结论：未发现逻辑错误、数据损坏、崩溃或客户端输入信任缺陷。** 40+ 高危补丁逐条验证通过：客户端 NBT 经 `readNbt`→`NbtAccounter.defaultQuota()`（2MB 上限）保护、服务端校验（throw/disconnect/Preconditions）扫描确认无一处被补丁削弱、无新增 static 可变共享状态、事件门控的"零监听器"假设与默认值逐文件实证正确、对象复用（scratch-list/碰撞 list/压缩池）的重入与并发声明均成立。

子代理报告的 3 项数据持久化发现经复核：
- **0134 跨包访问（HIGH）→ 误报**：`ByteBufCodecs.papoNbtSerializationContext` 源码虽为 package-private，但 Paperweight 在编译期宽化为 public（实跑 `--rerun-tasks --no-configuration-cache` 干净编译 BUILD SUCCESSFUL，javap 确认字节码为 `public static`）。非 bug。
- **0068/0075 LongArrayTag 批量读写峰值内存放大（MEDIUM）→ 真实，本版修复**（见下）。
- **0085 writeFixedSizeLongArray 溢出守卫缺失（LOW）→ 理论性不可达**（仅被协议固定尺寸调用，约几千 long；若误传会抛清晰异常而非静默损坏），暂不改。

## 新增修复（0107/0112）：物品拾取动画丢失（行为 bug）

- **问题**：`ItemEntity.playerTouch` 的零监听器快路（0107 PlayerAttemptPickupItemEvent 门控 + 0112 PlayerPickupItemEvent/EntityPickupItemEvent 双门控）在三个拾取事件均无监听器时（常见情况），跳过了设置局部 `flyAtPlayer` 的事件块，而 `flyAtPlayer` 初值为 false。但 `PlayerAttemptPickupItemEvent`/`PlayerPickupItemEvent` 的 `flyAtPlayer` 字段**默认均为 true**，原版零监听器下 `flyAtPlayer=true` → `entity.take(this,count)` 触发"物品飞向玩家"拾取动画。Papo 快路下 `flyAtPlayer=false` → **拾取动画丢失**（玩家看到物品消失而非飞向背包）。
- **影响**：纯视觉/用户交互回归（物品仍正确进入背包，`getInventory().add` 不受影响，无数据丢失/复制）；但属可观察的行为差异，违反"行为等价"红线。
- **修复**：`ItemEntity.playerTouch` 局部 `boolean flyAtPlayer` 初值 `false` → `true`（0107 补丁）。全零监听器情形恢复默认 true（保留动画）；其余 listener 组合（420/450 行）在消费前覆写该初值，故 init=true 对所有情况正确。0112 快路注释同步勘正。
- **验证**：compileJava + 全量 test（--rerun-tasks，无缓存）BUILD SUCCESSFUL。

## 新增修复（0068/0075）：LongArrayTag 批量读写内存阈值下调

- **问题**：LongArrayTag 批量读/写会同时持有 `long[_int]`（8n）与临时 `byte[_int<<3]`（8n），峰值 16n（vanilla 逐元素流式仅 8n）。LongArrayTag 无 Spigot 尺寸上限，且区块加载走 `NbtAccounter.unlimitedHeap()`（不限制），故恶意/损坏的 region 文件（世界导入、插件、磁盘损坏等半可信磁盘输入）可在 8n < 剩余堆 < 16n 时触发 OOM（DoS）。
- **威胁边界**：客户端 NBT 不受影响（走 `readNbt`→2MB 上限，放大本就受限于 4MB 峰值）；合法数据（高度图 256、生物群系、结构数据等）远小于阈值，不受影响。
- **修复**：批量阈值由"仅溢出守卫 `Integer.MAX_VALUE/8`"下调为"内存安全阈值 `1<<20`"（0068 读侧 + 0075 写侧对称）。`_int <= 1<<20`（临时缓冲 ≤ 8MB，覆盖所有合法数组）走批量快速路径；更大/对抗性数组回退逐元素流式（vanilla 8n 峰值，消除 2x 放大；`_int<<3` 仍在 int 范围故同时覆盖原溢出守卫）。
- **等价性**：仅改"批量 vs 流式"的尺寸分界，输出字节与逻辑完全一致；IntArrayTag 有 Spigot `1<<24` 上限不动。
