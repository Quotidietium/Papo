## 新增优化（0218-0219）

### 0218 — Connection.send 立即发送判定析取重排
- 原判定序使 play 阶段主线程发送的**非白名单包**（实体移动/数据/方块/区块更新——绝大多数流量）先走完 ~20 个 instanceof 全 miss 才落到恒真的主线程臂。两臂均为无副作用纯谓词且导向同一调用——求值序不可观察，重排后廉价臂短路。
- JMH 0.923 → 0.534 ns/op（**1.73×**，CI 不重叠；绝对节省 ~0.4ns/包）。布尔等价矩阵自检 ALL OK。零风险纯重排。

### 0219 — ServerEntity.addPairing 配对包列表预尺寸
- `new ArrayList<>()`（容量 10）→ `new ArrayList<>(4)`（sendPairingData 常态 2-4 包）；区块加载突发期每次实体配对省超额分配。零风险。

## 否决评估：主线程每包 eventLoop().execute 批量化（未落地）

高价值候选经完整实现 + 自检 + 两轮实测后**否决**（实测无收益即撤纪律）：
- CLQ 版回退 **4.8×**（跨线程 CAS + 每元素 Node 分配）；netty MPSC 修正版仍劣化 1.49×。
- **机制前提证伪**：netty 的 `NioEventLoop.wakeup` 带 CAS 守卫（每 park 窗口至多一次唤醒）+ 64 任务/批处理——原版逐包任务机制早已被 netty 内部摊销，理论收益不存在；且改动属 0209 同类跨线程复杂度。
- 判例沉淀至 optimizations.md（"消除每任务开销"类候选先核实运行时内建摊销；跨线程队列选型必须实测）。基准类与两轮数据留档。
