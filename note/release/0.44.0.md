- 基线：Minecraft 1.21.11 / Paper 上游
- 产物：`paper-server/build/libs/Papo-1.21.11-0.44.0.jar`
- 红线保持：默认行为等价、API 零变更、游戏版本红线 1.21.11 不变
- **游戏版本红线：始终保持 Minecraft 1.21.11**
- 性质：**多玩家网络稳定——多观众区块包构造缓存**（批次 70，网络主线）

## 新增优化（0241）

### 0241 — 多观众区块包构造缓存（LevelChunk 序列化负载跨观众复用）
区块发送主路径此前对**每个观众**完整重序列化同一 chunk（heightmaps clone + 24 section 调色板序列化
+ buffer 分配）：N 玩家看同一 chunk = N 次全量序列化，登录/跑图突发/群体迁移时主线程毫秒级放大。

- `LevelChunk` 每实例版本计数（`papoChunkDataVersion`，setBlockState / setBlockEntity /
  removeBlockEntity / setBiome 四处 bump）+ 序列化 heightmaps/buffer 缓存；观众命中时复用，
  chunk 变更即失效。
- **BE 标签与光照数据逐包新鲜构造**（其内容变化无 chunk 级信号——缓存会让后加入观众拿到永久
  陈旧 BE/光照，可观察回归红线不可越）。
- anti-xray `shouldModify == false` 才走缓存（Paper 默认 `antiXray.enabled=false` 命中）；启用时
  原路径逐字保留。`modifyBlocks(packet, null)` 两种实现均恰为 setReady(true)，新构造器行为逐字一致。
- 线上字节逐字节相同（**带宽中立**）；收益=多观众突发的主线程 CPU/GC 消除（N 次序列化 → 1 次）。

## 基准

- ChunkPacketCacheBench 模型：完整构造 2597.676 ± 271.850 ns/op → 命中 **24.623 ± 0.363 ns/op
  （≈105×，CI 完全分离）**；未命中与原路径持平；`-prof gc` 分配 **43992 → 248 B/op（177×）**。
