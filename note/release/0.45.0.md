- 基线：Minecraft 1.21.11 / Paper 上游
- 产物：`paper-server/build/libs/Papo-1.21.11-0.45.0.jar`
- 红线保持：默认行为等价、线上字节恒等、API 零变更、游戏版本红线 1.21.11 不变
- **游戏版本红线：始终保持 Minecraft 1.21.11**
- 性质：**多玩家网络稳定——共享区块包实例 + 压缩输出 memo**（批次 71，批次 70 的复合续作）

## 新增优化（0242）

### 0242 — 跨观众共享 chunk 包实例 + DEFLATE 压缩 memo
多观众发送同一 chunk（登录/跑图突发/群体迁移）时，每连接对**逐字节相同**的包各自 DEFLATE
（实测 41KB ≈ 224µs/观众；Linux libdeflate 下 64KB level-6 ≈ 1.3ms）——批次 70 消除重复序列化后，
这是每观众主导成本。

- **共享实例**：BE-free 且（chunk 数据版本, 光照版本）未变时，`ChunkHolder` 向所有观众返回同一个
  `ClientboundLevelChunkWithLightPacket`（FeatureHooks 刷新路径的跨玩家共享先例延伸到主发送路径）。
- **光照版本信号**：`sectionLightChanged` 计数（光照引擎 `onLightUpdate` 驱动，与 vanilla 增量
  光照广播同源同完备性）。已知亚 tick 窗口由排队通知的增量光照包同 tick 自愈（无持久 desync）。
- **压缩 memo**：共享实例携带单槽 memo——首连接压缩后快照自描述段 `[数据长 varint][压缩负载]`，
  后续连接 memcpy 直放。threshold 戳 + 压缩级别纪元键控；0217 身份通道传递；外来 buffer 走原路径。
- **带宽中立**：命中与未命中路径线上字节逐字节相同（8 观众真实 Deflater 对拍全等）。

## 基准

- SharedChunkWireBench（41,189B 载荷，压缩比 3.99× 贴近真实 4.9×）：每观众 223,680.700 ± 4,933
  → 命中 **3,509.720 ± 87 ns/op（≈63.7×/观众，CI 完全分离）**；填充路径与原路径持平。
- 20 观众 × 64 chunk 突发 ≈ **282ms CPU 消除**（此前为网络 event loop 的主要突发负载）。
