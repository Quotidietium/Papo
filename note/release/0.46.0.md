## 新增优化（0243）

### 0243 — ClientboundLightUpdatePacket 广播压缩 memo
`ChunkHolder.broadcastChanges` 把**同一个**光照更新包实例发给每 chunk 全部追踪玩家（黄昏/黎明
光照传播期每 tick 多 chunk × N 玩家）——每连接对相同 10-40KB 各自 DEFLATE。本批让该包接入
0242 的 `PapoSharedWireMemo` 机制（实现 Carrier + 构造挂 memo）：首连接压缩、后续连接 memcpy。

- 单文件改动，无新机制面（threshold 戳/level 纪元/0217 身份通道/外来 buffer 回退全部沿用 0242）。
- 包为每次广播新建（瞬态），memo 随包 GC——无长期内存面。
- 带宽中立：命中与未命中路径线上字节逐字节相同。

## 基准

- LightBroadcastBench（32,770B 光照型载荷，压缩比 1.98×）：每观众 311,336.888 ± 9,197 → 命中
  **4,462.938 ± 256 ns/op（≈69.8×/观众，CI 完全分离）**；填充路径与原路径持平。
- 黄昏传播期外推：50 chunk × 20 玩家 ≈ **292ms/s CPU 消除**（此前为各连接 event loop 持续负载）。
