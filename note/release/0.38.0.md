## 新增优化（0226/0227）

### 0226 — join 静态配置包按 reload 纪元缓存（本批主项）
- 原本**每个玩家 join** 的配置阶段在主线程重建：UpdateTags 包（vanilla 实测 625 tag / 4377 条目 id 查找）+ 24 个 RegistryData 包（371 条目；**known-packs 不匹配的客户端（典型 ViaVersion 转译）每 join 全量 NBT 编码数毫秒 + ~100KB wire**）——而内容在两次资源重载间逐字节恒定。
- 改为静态缓存，`reloadTagData()`（唯一失效收口）以新广播实例换缓存。包对象共享为 vanilla 既有行为（broadcastAll 同实例先例）；两包无 per-send 钩子，编码只读。
- 基准：模型 0.21ms/join 主线程构建 → 0.96ns 缓存读（survey 实测构建估 0.3-1ms；Via 部署下另省数毫秒 + ~100KB/客户端）。
- 高换人服务器（hub/小游戏）join 风暴下收益线性放大。

### 0227 — PrepareSpawnTask 双重读盘去重
- start() 与 spawn() 同一 join 各一次 `loadPlayerData`（磁盘读+gzip+NBT 解析+datafix 全树，主线程 ×2，上游 vanilla 同病）→ 复用首次结果（含新玩家 empty 情形）。
- 基准：gzip 模型 2.01×；真实场景含磁盘+datafix 节省更大（背包重玩家毫秒级/次 join）。
