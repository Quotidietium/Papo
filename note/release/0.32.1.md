# Papo 0.32.1 发布说明

- 基线：Minecraft 1.21.11 / Paper 上游
- 产物：`paper-server/build/libs/Papo-1.21.11-0.32.1.jar`
- 性质：**bugfix**（实体爆炸卡服防护 + 回退有并发缺陷的 0209）
- **游戏版本红线：始终保持 Minecraft 1.21.11**

## 背景（用户报告）

在领地保护（Residence）区域破坏草丛（TallGrass）时，某掉种子插件在 BlockBreakEvent 被领地保护取消的情况下仍无限 `world.dropItem` 生成种子 ItemEntity（草被取消破坏、恢复，但插件照常掉种子，循环往复）。结果：主线程因处理海量实体（每 tick 物理合并 O(n²) + 追踪发包）而卡死，所有玩家连接超时；重连时同步累积实体再次卡死（"延时爆炸"）。**经向用户确认为主线程卡死（非异常崩溃，无崩溃堆栈、无 hs_err），服务器进程未停、玩家均超时**。

根因逐项确认（详见 [optimizations.md](../optimizations.md)）：
1. `ServerPlayerGameMode.destroyBlock`：BlockBreakEvent 取消时走"不掉落、不破坏、只发 BlockUpdate 纠正客户端"分支——左键破坏路径 **Papo 完全未改**（门控只改右键 interact）。
2. 种子是插件自己 `dropItem` 生成（绕过 `captureDrops`），属插件行为，Papo 无法干预。
3. ItemEntity 合并/拾取/tick 全是原版逻辑，**Papo 未破坏合并**（`callItemMergeEvent` 零监听器快路返回 true=允许合并，正确）。
4. **关键防护缺失**：Moonrise tick 所有激活实体，**无 Spigot 的 `max-tick-time.entity` 超时跳过，也无任何 per-chunk/per-type 实体上限**（`spawn-limits` 不管 ItemEntity——MISC 被排除；`altItemDespawnRate` 是时间限制非数量上限）。
5. 结论：是 **Papo 与原版 Paper 共有的防护缺失**，非 Papo 回归。

## 修复

### 1. per-chunk 掉落物数量上限（补丁 0209，config-gated 默认关闭）

照抄 Moonrise 既有的同构参考实现 `enderPearlChunkCount`（per-chunk 末影珍珠计数），新增 per-chunk ItemEntity 计数：
- `ServerEntityLookup` 加 `papoItemEntityChunkCount`（Long2IntOpenHashMap），在 `addEntityCallback`/`removeEntityCallback`/`entitySectionChangeCallback` 三处维护（add++ / remove-- / 跨chunk old-- new++）。这是 Moonrise 实体生命周期的统一咽喉点，每个实体恰好一次（NoOp 兜底防重复），覆盖 ItemEntity 全部 7 条 discard 路径 + 区块卸载 + 换维度。
- `ServerLevel.addEntity` 在 captureDrops 块之后、`addNewEntity` 之前检查：目标 chunk 的 ItemEntity 计数 ≥ cap 时丢弃新 item（返回 false）。**放 captureDrops 之后**使合法的方块破坏掉落（被 captureDrops 捕获）不受影响，只有未捕获的掉落（如插件 `world.dropItem`）受约束。
- 配置（`paper-world.yml`，per-world）：`entities.spawning.item-entity-limit-per-chunk`，默认 **-1（关闭，vanilla 行为）**。服主按需开启（如 256）。

### 2. 回退原 0209（0.32.0 的 send-lambda 补丁，voidPromise 跨线程缺陷）

0.32.0 的补丁 0209 把 `Connection.doSendPacket` 从 event-loop 线程移到调用方线程（主线程），而 `doSendPacket` 在 `sendListener==null` 分支使用 `this.channel.voidPromise()`。netty 的 `voidPromise()` 文档明确要求**仅在 event-loop 线程使用**（无同步保护）——0209 破坏此前提，构成跨线程并发缺陷。0.32.0 release note 自标"未做 live 压测；单补丁可 revert"。本版回退 0209，恢复 `sendPacket` 的 `inEventLoop()` 判定 + event-loop 调度，`doSendPacket` 回到 event-loop 线程，`voidPromise` 使用恢复安全。无功能损失（仅恢复一个 per-outbound-packet lambda 分配）。

> 注：0209 的 voidPromise 缺陷症状通常是 netty 异常/玩家断连，**不匹配**本次"主线程静默卡死"症状——本次卡死的直接根因是实体爆炸（修复 1），0209 回退是顺带消除一个确凿的并发隐患。

## 配置示例（paper-world.yml）

```yaml
entities:
  spawning:
    item-entity-limit-per-chunk: -1   # -1=关闭(vanilla)；正值如 256=每区块最多 256 个掉落物，超出丢弃
```

## 验证

- compileJava（`--no-configuration-cache`）+ 全量 test BUILD SUCCESSFUL（零 FAILED）。
- 行为自检：默认 -1 时 `addEntity` 不做数量检查（行为同原版）；设正值时超限 ItemEntity 被拒绝加入。
- 0209 回退后 `Connection.sendPacket` 恢复 `inEventLoop()` 判定（Connection.java）。

## 兼容性

- API 零变更；游戏版本红线 1.21.11 不变。
- per-chunk 上限默认 -1（关闭），与 0.32.0 行为逐字一致；config 未加载时也跳过检查（`cap >= 0` 守卫）。
- 合法的方块破坏掉落（captureDrops 路径）不受上限影响。

## 残留说明

- 这是**服务器级损害控制**：根本解决需插件作者不在取消的破坏事件里掉种子。per-chunk 上限默认关闭，服主按需开启。
- per-chunk 计数已处理跨 chunk 移动；极端边界（实体在 section 状态变更中被移除，`Entity.setRemoved` 提前 return）计数可能不归零，但 add 检查的严格性保证防护有效（计数偏低=更宽松，不误杀）。
