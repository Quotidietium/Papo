# Papo 0.92.0（批次 160/161，R20）

R19 收敛判定的对抗复核轮：两处弱归因被推翻为可收割面并完成收割。

## 优化

1. **批次160：pre-carver 停机 NoiseChunk 释放（−11.4MB @ 12 bots/vd10）**
   - 病灶：批次143 的释放钩子在 CARVERS 出口（最后读点）；pre-carver 状态环（等
     邻居依赖/取消后停机）到不了钩子，318 棵 NoiseChunk 树（插值切片+密度子树+
     aquifer 缓存，~36KB/棵）随持有者终生驻留，规模随玩家边缘长度扩展。
   - 修复：`ServerChunkCache` 每 2048 game tick（~102s）主线程扫 holder，对停机
     ProtoChunk（排除 Imposter）周期释放 `ChunkAccess.noiseChunk`；恢复生成时由
     当步闭包按需重建（恒等三件套论证：跨步读面纯记忆化/Blender.of 与区域半径
     无关/在途步骤持局部引用）。`-Dpapo.noiseParkSweepTicks=N` 诊断门（≤0 禁用）。
2. **批次161：blockEntities 懒分配（−13,316 张空 O2O 图 ≈ 1.9MB）**
   - 病灶：`ChunkAccess.blockEntities` 每 chunk 构造即付 ~210B fastutil 图；自然
     地形绝大多数 chunk 终生无方块实体；ImposterProtoChunk 的继承字段被证明从不
     触碰（4,947 张纯死图）。
   - 修复：字段 `@Nullable` 懒分配；`papoBlockEntitiesView()` 不可变空视图（写
     穿透即抛，钉死只读契约）+ `papoBlockEntitiesWritable()` 首变更分配；19 处
     触点全改（ChunkAccess/LevelChunk/ProtoChunk/CraftChunk/CraftWorld）。
