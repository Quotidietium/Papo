## 新增优化（批次 87）

### prepare_spawn 事件驱动完成
相位分解实证：稳态 80ms 的 join 中 46ms 是纯 tick 量化等待——配置任务状态机只在
tick 边界推进（区块加载票据在 start 后的首个 tick 才被调度、future 完成要等下个
tick 才被观察，两级量化最坏 ~100ms）。现在 start 与各异步阶段完成回调统一经主线程
任务队列（包处理器与 placeNewPlayer 本就运行的 tick 间窗口）即时推进同一状态机，
完成转移 CAS 单发；包/事件序列逐连接完全相同，仅提前。
