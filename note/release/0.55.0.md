## 新增优化（批次 82）

### join 读侧预取（登录 RTT 窗口）
玩家加入时的三类读档——playerdata `.dat`（gzip+NBT+datafix）、stats JSON、
advancements JSON——此前全部在主线程同步执行。现在在登录认证完成时（距消费点
至少一个客户端 RTT）即挂到各自文件的有序写链上异步预取，主线程消费点等待的
通常是已完成的 future：

- 读挂在与存档写相同的 per-文件有序链上，快速重连的读后写可见性保持；
- 读任务使用 BLOCKING 优先级（vanilla 同步加载同款），IO 池饱和时主线程
  依然优先于排队的 region IO，不以流畅度换吞吐；
- `.offline-read` 重命名等副作用留在主线程消费点原位置，登录中断不产生
  提前副作用；无预取/异常/停机时逐字回退原同步路径。

## 基准
