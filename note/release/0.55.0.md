# Papo 0.55.0 发布说明

- 基线：Minecraft 1.21.11 / Paper 上游
- 产物：`paper-server/build/libs/Papo-1.21.11-0.55.0.jar`
- 红线保持：默认行为等价、API 零变更、游戏版本红线 1.21.11 不变
- 性质：**多核调度④——join 读侧下放（登录窗口预取）**（批次 82-84）

## 新增优化（批次 82，经批次 83/84 实测迭代后的终态）

### join 读侧预取（登录 RTT 窗口）
玩家加入时的三类读档——playerdata `.dat`（gzip+NBT 解析）、stats JSON、
advancements JSON——此前全部在主线程同步执行。现在在登录认证完成时（距消费点
至少一个客户端 RTT）挂到各自文件的有序写链上异步预取，主线程消费点等待的
通常是已完成的 future：

- 读挂在与存档写相同的 per-文件有序链上，快速重连的读后写可见性保持；
- 读任务入队 NORMAL 优先级（无人等待时不抢占区块 IO）；消费点若未完成则
  升级 BLOCKING（与原版同步加载同语义，主线程不饿死）；
- **datafix 留在主线程消费点与原版逐字相同**（突发压测实证：移到 IO/worker
  池会与区块管线竞争，端到端反而变慢）；
- `.offline-read` 重命名等副作用留在主线程消费点原位置；无预取/异常/停机时
  逐字回退原同步路径；断连钩子丢弃未消费预取。

### 并发登录修复
并发 join 时 authenticator 多线程触发 `LevelStorageAccess.getLevelPath` 的
HashMap 缓存并发修改异常（批次 84 压测抓出）——stats/adv 目录改为构造期主线程
一次解析。

## 基准

- JoinReadPrefetchBench（真实 concurrentutil 池，20 人突发）：主线程读侧成本
  15.45ms → 0.04ms（**≈380×**）；零 RTT 最坏情形恒不劣于同步。
- 真实服务器 20-bot 并发 burst（fat 老 .dat，双向序 ×3 轮）：与 0.54.0 统计
  持平且均值均略优 30-50ms；240 join 零异常、关服契约与产物全部合规。
