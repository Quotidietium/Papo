# R10（批次150）：结构模板驻留解耦——piece 惰性取 + 有界管理器缓存（0.87.0 → 0.88.0）

- 日期：2026-10-10
- 版本：0.87.0 → 0.88.0（补丁 0273）
- 前置：0.87.0 树配对浸泡重基线化 + 转储普查残余非内容簇归因（本会话完成）。

## 0. 摘要

0.87.0 普查残余非内容簇两大候选归因完毕：**voxel shape 族（AABB 345,829 ≈
51.4MB 总簇）是每注册方块状态碰撞形状缓存的注册表界固定成本**（29,492 个
BlockStateBase$Cache × ~4.8 形状/状态），随注册表生死、不随游玩增长——红线
判负出局；**结构模板簇是无界增长**：495,771 个 StructureBlockInfo（11.9MB）
+ ~495k 个 BlockPos（11.9MB）+ palette/list 数组 ≈ **26-28MB（3.4%）**，仅由
412 个 StructureTemplate 持有，全部挂在全服单例 StructureTemplateManager 的
无界 `structureRepository` 并发映射里（vanilla 从不驱逐；datapack reload 才
clear）。

钉扎审计发现单纯给映射加上界**不生效**的隐患：TemplateStructurePiece 强持
`protected StructureTemplate template` 字段（getOrCreate 取得），而 piece 存
于 StructureStart、StructureStart 存于**常驻区块**——生成结束后管理器驱逐也
释放不了被存活 start 钉住的模板。修复是双面的（0273）：

1. **piece 惰性取**：TemplateStructurePiece 改持 manager + 解析好的
   Identifier，`template()` 访问器用时经 getOrCreate 现取；该字段本来就不序列
   化（vanilla 一直只存模板名），盘格式零变化；postProcess 每次 pass 取一次
   （同一次放置内单实例）；模板放置期间不可变，miss 重载恒等重现内容。六处直
   接字段访问（Shipwreck×3/OceanRuin/NetherFossil/RuinedPortal，全为放置期
   getSize/getBoundingBox）改走访问器。
2. **有界缓存 PapoStructureCache**（运行时类型替换，声明字段类型保持 `Map`
   保插件二进制兼容）：idle-TTL 120s 驱逐 + MinecraftServer.tickServer 每 512
   tick（≈25.6s）清扫（生成结束后世界生成不再触碰缓存，无钩子则永不收缩）；
   **put 即保护**——vanilla getOrCreate 先 get()（tryLoad 路径）只在无源可载
   时才 put 新建，保护域恰为"可能未保存的程序性工作"（getOrCreate 新建空模
   板 + 全部 Bukkit register/load-with-register）；tryLoad 背书的条目永远可重
   载故可驱逐；**全读路径打访问戳**（get/containsKey/computeIfAbsent/
   entrySet/values 迭代）——插件轮询原始映射（Bukkit getStructure/
   getStructures）的条目永远热，API 语义逐字节不变；256 条可驱逐上限按最老戳
   先逐防病态世界；reload clear 连保护域一并清（vanilla 语义）。

**配对浸泡门对（12 bot、6,096 vs 6,046 区块 −0.82% 门内、零错误、双退出）：堆
782,611 → 757,348 KB = −25,263KB（−3.23%）**；同会话又补两腿转储复跑：A-087 复
腿 775,404KB（与首 A 腿差 −0.9%，会话内漂移）× B-088 转储腿 757,348KB，区块
6,048 vs 6,046（−0.03%，**近完美配对**）= **−18,056KB（−2.33%，保守取值）**。
归因（转储对直方图逐类差分）：StructureBlockInfo −227,169（−5.45MB）、
BlockPos −222,500（−5.34MB）、Object[] −1.69MB、String/Integer/ArrayList/
NBT StringTag −5,186/CHM 节点与表/LongAdder ≈ −1.4MB，类级净 −15.4MB ≈ 85%
闭合（余为堆填充 +443KB 与独类抖动）；StructureTemplate 412 → 155、Palette
468 → 169、JigsawBlockInfo 1,215 → 704；B 腿少 50 区块（≈−4.3MB 内容）。残留
268k infos 是 **TTL 热窗边界效应**：测量点 = 驻留+120s 恰逢 TTL，行走末段与
驻留早段区块精炼（邻居 postProcess 重戳模板）落在 120s 窗内——补充
B-088@驻留+240s 普查腿证实稳态全驱逐（见 §4）。

## 1. 角度选择与算术

- 立项算术：412 模板 × (495,771 infos × 24B + ~495k BlockPos × 24B + 列表/
  palette/NBT) ≈ 26-28MB（r9 会话普查 refattr + 直方图）；无界性：模板数随探
  索面积单调增（每个村庄/沉船/掠夺站/化石各载入若干模板，永不释放）。
- shape 族判负依据：ArrayVoxelShape 141,516 ≈ BitSetDiscreteVoxelShape 140,060
  ≈ CachedToAABBs 141,161 三者同数 = 每 BlockStateBase$Cache（29,492）~4.8 个
  碰撞/遮挡/射线形状；AABB 345,829 ≈ 形状族 ×2.45（每形状的盒列表）。全部由
  注册方块状态的形状缓存持有，注册表界=vanilla 恒定成本，动它=碰注册表语义
  （红线），出局。
- 每模板均值 ~65KB（大结构 village/trial chamber 数千 infos，小结构数十），
  病态差异大——TTL 驱逐对大小无偏，256 上限只防条目数不防字节（字节界由
  热集决定：生成活跃期工作集自然驻留，结束后全释放）。

## 2. 设计（0273）

### 2.1 钉扎审计：为什么"只加上界"不生效

TemplateStructurePiece.template 是 protected 强字段，两条构造路径（世界生成
+ NBT 反序列化）都经 getOrCreate 取实例；piece → StructureStart → 常驻区块
数据。浸泡场景里 start 多数在放置完成后随周边生成结束而空置（dump：
StructureStart 仅 68、TemplateStructurePiece 0——模板几乎纯由管理器映射持
有），但真实服务器大视距下，含非空 start 的村庄区块常驻即钉住全部 piece 引
用的模板。惰性取把钉扎链剪断：驱逐后 miss 重载 = 新实例，而放置结果只依赖
内容不依赖实例同一性。**身份翻搅边界**：若插件/datapack 在世界生成进行中重
注册同 id 模板，vanilla 已建 piece 用旧实例、新 piece 用新实例；Papo 全部
piece 用最新注册——admin/开发动作与生成并发的极端边角，判例记入（见 §5）。

### 2.2 PapoStructureCache：语义保持的三个面

- **Map 契约面**：声明字段类型保持 `Map<Identifier, Optional<StructureTemplate>>`
  （字段描述符不变，编译期直引插件零破坏）；运行时类是 CHM 子类，put 返回旧
  值/get 同实例/computeIfAbsent 不重跑/remove 返回值——单测逐条断言。
- **Bukkit 面全保真**：CraftStructureManager 六处原始映射操作逐一核对——
  registerStructure/unregister/delete（put/remove，put 即保护）语义不变；
  loadStructure(register=true) 的 put 落保护域（vanilla 也是永不驱逐）；
  getStructure（map.get）/getStructures（entrySet 迭代）经访问戳保持热——
  轮询插件观察不到条目消失；save（map.get 亦戳）。
- **保护域精确性**：vanilla getOrCreate 的结构是"先 get()（computeIfAbsent→
  tryLoad），present 即返回，miss 才 new+put"——put 覆写即捕获**且仅**捕获
  "无源可载的新建"与 Bukkit 显式 put；tryLoad 能载的 id（世界生成热路径）永
  走 computeIfAbsent，不进保护域。getOrCreate 新建的空模板（未知 id，如坏
  datapank 引用）受保护直到 reload clear——与 vanilla 永驻语义一致，严格更优。

### 2.3 清扫钩子

MinecraftServer.tickServer 在 `ticksUntilAutosave--` 后挂 `(tickCount & 511)
== 0` 调 papoMaintenanceTick()（主线程，≈25.6s 一次；清扫 O(缓存条目数) 且无
空闲条目时零工作）。清扫间隔内置去抖（now−lastSweep < 25s 直接返回）。并发
安全全靠 CHM 条件语义；检查与删除间重插入的竞窗后果 = 下次访问重载，正确性
无虞。

## 5. 判例

1. **grep 枚举不许截断**：`head` 截断漏了 RuinedPortalPiece:146 的直接字段
   访问，编译才抓到。收口动作=全仓无截断复查 `this\.template\.`。审计面枚举
   的完备性不能靠采样。
2. **加界前先找钉扎链**：缓存上界的收益 = 可驱逐条目集的真实可达性。holder
   图（piece→start→常驻区块）审计必须在实现前完成，否则上界只是装饰。本场景
   dump 里 piece 恰好零常驻（start 空置），但常驻非空 start 的世界（真实服务
   器）会让纯映射上界归零——惰性取不是锦上添花而是上界生效的前提。
3. **保护域按进入路径划，不按内容猜**："put 即保护"恰好捕获 vanilla 语义里
   全部不可重载来源（无源可载的新建 + Bukkit 显式注册），无需"看起来是空模
   板"之类内容启发式——启发式在"插件建了恰好空的合法模板"时必然误伤。
4. **读路径打戳是原始映射暴露面的保真义务**：只要插件能拿到原始 Map 引用，
   缓存的每个优化都必须假设有轮询者；get/containsKey/computeIfAbsent/视图
   迭代全打戳后，驱逐只影响"无人读过 120s"的条目——语义上等价于"活跃集"的
   定义本身。
5. **TTL 与测量点的相位**：驻留型基准的测量延迟若等于 TTL，残留恰为热窗半
   衰减——报告稳态需一条延迟 ≥ TTL+清扫间隔 的补充腿。
