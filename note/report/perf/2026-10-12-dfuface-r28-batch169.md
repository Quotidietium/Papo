# R28（批次 169）：DFU 盘载旧数据转码面——实测判负（版本保持 0.94.0）

日期：2026-10-12 ｜ 轮次：R28 ｜ 判定：**判负**（零服务器代码变更，benchmark 工具两件入库）

## 动机

历轮（R24 census、R26 清扫）浸泡世界均为**全新生成窗**——DataVersion 恒等于当前版本，
数据修复（DFU/DCF）转码路径从未执行，该面一直 absent。本轮构造**盘载旧数据重载腿**：
把已有世界全部区块降版后由服务器重载，强制全量升级链执行，实测转码面的驻留与分配画像。
（R24 残余簇 DirectMethodHandle 829 trips / Ap2.fillArray 1,062 trips 已在 R24 §8 判负，
本轮未重开。）

## 工具（两件入库 `benchmark/src/papo/bot/`）

- **RegionDowngrade.java**：Anvil `.mca` 原位 DataVersion 降级器。8KB 头（1024×4B 位置 +
  1024×4B 时间戳）扫描，逐区块解压→根复合标签遍历定位 DataVersion→改写→重压缩；
  新载荷 ≤ 原扇区数即原位回写（无需重定位），否则抛错拒改。**勘误（判例）**：NBT 数值标签
  宽度表 TAG_Long=**8B**（此前误按 4B 跳过导致根遍历错位读 END 抛 AIOOBE——正确宽度：
  Int/Float=4B，Long/Double=8B）。用法 `java papo.bot.RegionDowngrade <worldDir> <target>`
  （0=只读报告）。
- **DfuSoakCensus.java**：盘载旧世界浸泡腿。复制源世界→全 region 降版（本轮 3465=
  1.20.1，距 1.21.11 跨数百 schema）→起服（端口 25593，同 MemSoakVerify 服务端属性，
  spectator/peaceful/seed papa90）→12 bot 专用定长池复走源世界同款放射走廊（2π·i/12），
  `-Ddfusoak.jfr=true` 于 +25s 起 60s JFR（ObjectAllocationSample#threshold=1ms），
  驻留末双 GC+直方图+heap_info；门=bot 全完成+logErrors=0+exit 0。

## 腿结果（gate 全绿）

源世界：R25 12-bot 浸泡残留（16 region / 10,296 区块）。降版：**10,296/10,296 全部 3465，
0 重定位拒绝**；服务器正常启动（upgrade 路径无异常日志），12 bot 走廊完成，
`DfuSoak.gate logErrors=0 exited=true`；驻留末 heapUsedKb=781,960（4G 堆，young 183 区）。

## 归因

### 驻留面：DFU 执行零增量驻留（位相同直方图证据）

驻留末直方图首次可见 `com.mojang.datafixers.types.templates.*` 大簇：
Product$ProductType 22,617/724KB、Tag$TagType 18,133/580KB、Sum$SumType 17,729/567KB、
Const 34,273/548KB、Named$NamedType 15,543/497KB、Sum 14,931/358KB、Product 14,021/337KB、
Tag 13,744/330KB（合计 ≈151k 实例 ≈4.4MB）。**关键对照**：R27 全新生成腿（未执行任何
DFU 转码、且 bot 数 60≠12、世界内容不同）的同名行**逐位相同**——22,617/18,133/17,729/
34,273/15,543/14,931/14,021/13,744 全等。结论：该簇是**启动期 schema 注册常量**（数百个
schema 版本注册时构建的 DSL 类型图），与是否执行转码、世界状态、在线规模完全无关；每台
服务器等额支付，DFU 执行**零增量驻留**。DCF 侧（R22 曾见 NBTMapType 6,956/Dynamic
7,183 的实体重世界）本腿驻留末 NBTMapType/Dynamic 行缺席——盘载升级腿零 DCF 驻留。

### 分配面：DFU 归因 1.7%，大头是 codec 反序列化机器本身

JFR 60s 窗（+25s 起，覆盖 10,296 区块升级突发）1,819 样本/采样权重 3,842MB，
按首 datafixers/dataconverter 帧归因：**DFU 归因 69 样本/66.0MB（1.7%）**
（util.Pair.of 36.6MB + MCDataConverter.convertWithSubVersion 25.3MB；摊销 ≈6.4KB/区块，
全瞬时）。权重前位全是 NBT→codec 反序列化通路：ShortArrays.forceCapacity 487MB、
Object2ObjectOpenHashMap ctor 448MB、DataResult$Success.map 389MB、
PalettedContainer.unpack 252MB、LongArrayTag.readAccounted 158MB——与 R24 判例一致
（sampler 权重=线程自越界以来累计，仅作量级区间），且全部为**瞬时搅拌**（驻留面已证零增量）。

### 直方图差分（DFU 腿 vs R27 基线）

大额差全部由 12-vs-60 bot 规模差解释（advancement 监听器族随在线玩家数、区块族
PalettedContainer/Section/ShortList/Ticket/ChunkCompletion 随加载区块数）。唯一 DFU 侧
超额：SWMRNibbleArray 170,693 vs 96,708（+74k）——降版→升级后光照数据重物化（内容依赖，
世界状态性，非服务器代码面，且 1/5 的 bot 数下总 heap 781,960KB 仍低于基线 1,013,123KB）。

## 判定：判负

1. **无收割面**：转码引擎状态全为启动常量（位相同证明），执行增量驻留为零；瞬时分配 66MB/
   全程，摊销微不足道。无可"释放/池化/延迟"的对象面。
2. **红线禁止重写**：DFU/DCF+codec 反序列化是**旧世界兼容性本体**（跨数百 schema 版本的
   数据保真）。重写引擎、缓存类型模板（已是常量，缓存=无操作）、复用 DataResult 实例
   （Success 不可变值语义+lifecycle）均触兼容/语义红线。
3. R24 残余簇（DirectMethodHandle/Ap2.fillArray）维持 R24 §8 判负不重开。

**判例（入库）**：①"零增量驻留"的最强廉价证据=**与未执行路径基线的位相同直方图行**
（无关变量全不同仍逐位相等 → 启动常量，比逐类引用链归因更不可辩驳）；②工具勘误：NBT
根遍历宽度表 Long/Double=8B（4B 误跳=标签流错位）；③旧数据面腿必须先验证降版覆盖率
（10,296/10,296）再起服，杜绝新旧混合窗污染归因。

零服务器代码变更、零补丁、零版本 bump（0.94.0 保持）。benchmark 新增
RegionDowngrade.java + DfuSoakCensus.java 入库；原始数据留
`benchmark/results/dfusoak-1791669993653/`（burst.jfr/class_histogram.txt/heap_info.txt）。
