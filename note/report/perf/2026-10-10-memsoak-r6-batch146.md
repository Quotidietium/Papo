## 0. 摘要

在两个反序列化选择点（`CompoundTag.papoReadUtf`——compound 键与 StringTag 值的
唯一读取路径；`AdvancementProgress.CODEC` apply——每玩家进度判据键）接入有界
规范化池，连续实现三个准入设计并全链验证（单测、重放、编译、配对浸泡）：

| 设计 | 准入规则 | 结局 |
|---|---|---|
| v1 先到先得 | ≤48 字符首次即入池（上限 16k） | 池被早期一次性串冻结于垃圾词汇；浸泡 −22,897 实例（≈−1MB），目标种群未动 |
| v2 计数草图 | 4-bit 计数槽二见准入 | 被自己的单测证伪：碰撞误收 2,773 个一次性串；持续流量饱和后退化为准入恒真。未浸泡即弃 |
| v3 精确近期窗口 | 2,048 个不同首见即整窗轮转，仅窗口内二见入池 | 配对浸泡 −21,773 实例（≈−1MB）与 v1 等效；逐值普查证明 Name ×6,964 / has_the_recipe ×2,916 / north ×3,149 与无池基线逐字一致——论文目标种群零命中 |

结论：**通用共享池的三个准入设计都不能命中 7~9MB 论文目标**。机制 = 并发首见
洪峰（12 个并发 .dat 解析 + worldgen 模板 NBT）下 2k 窗口在任一值的两次出现之间
已被其他线程的首见灌满轮转，跨源复发永远落在新窗口。把窗口/池放大到真能接住
（窗口 ≈50~100k + 池 ≈64k）所需状态 ≈8~9MB ≈ 论文目标本身——**算术闭包**：
无论第四个设计怎么设计，净收益趋零。可达面拆账（§4）：boot 常量占大头不可达、
热路径有性能面、join-only 判据键 ≈2.2MB（0.25%）低于行动线（对照批144 对
15.8MB/1.8% 的否决；已落地最小收益为批145 的 0.81% 且零语义面）。

**处置：运行时改动全部回退**（内仓 reset 回批次145 提交；补丁序列重生成并逐
hunk 验证等价；版本回 0.84.0；0.85.0 jar 删除）。批次146 以负结果判例入库，
String 规范化角度就此关闭。

## 1. 三设计时间线与实测

### 1.1 v1 先到先得（首版 0.85.0）

全局池 cap 16,384、长度 ≤48 门槛，首次见到即入池（零额外分配：首见实例自身
成为规范实例）。单测 6 项全绿（共享语义、直通规则、NBT 字节恒等往返、并发
收敛、容量冻结、一次性洪泛）。配对浸泡（0.84.0 vs 0.85.0-v1，区块 +43 配对）：

- String 实例 388,396 → 365,499（**−22,897**）；堆 864,220 → 867,142 KB（区块
  增量掩盖，无效差分）。
- 普查复测（该腿转储未触发——脚本机制缺陷，见 §3 附注）：无逐值数据。

判负机制：worldgen/启动期的一次性串（各结构 NBT 杂项）先到先入，16k 池位在
目标种群（玩家 .dat 读取）到来前已被冻结；−22.9k 回收的是冻结前恰在池内的
杂项词汇复发。

### 1.2 v2 计数草图（未达浸泡）

固定 32KB 的 4-bit 计数槽按 hash 记首见次数，二见才入池。单测
`oneOffFloodDoesNotConsumePool` 直接证伪：20,000 个一次性串经碰撞误收
**2,773 个**入池；更深处，持续首见流量终将饱和所有槽位使准入退化回恒真——
回到 v1 的冻结命运。设计废弃，教训入 v3 注释。

### 1.3 v3 精确近期窗口（第二版 0.85.0，全链验证 + 配对浸泡 + 转储普查）

`RECENT` 精确 CHM（无碰撞）记首见，每 2,048 个不同首见整窗轮转清空；仅窗口内
二见者入 `POOL`（cap 16,384 不变）；首见原样返回、二见自身入池为规范实例、
三见起命中池。单测 6 项全绿（含 20k 一次性洪泛零误收——精确窗口无碰撞）。
全链：rebuildPatches + applyPatches 重放 EXIT=0 + compileJava --rerun-tasks +

### 1.4 机制与算术闭包

并发首见洪峰下，共享 2k 窗口的寿命 = 2,048 ÷ 首见速率。12 个并发 .dat 解析 +
worldgen 模板解析的首见速率（万级/秒）使窗口寿命 ~100ms 量级；任一目标值的
跨源复发间隔（跨 bot ≈400ms 错峰、跨模板一遍）远超窗口寿命 → 二见永远落空。
单源密集复发（同模板内 north ×N）本可在窗口内二见——但普查显示连 north 也
未收拢，说明并发交错已把单源复发也稀释到窗口外。

**算术闭包**：要接住跨源复发，窗口须容纳洪峰期间全部不同首见（估 50~100k 瞬态
≈5MB 级）+ 池须容纳完整 worldgen 词汇（≈64k × ~56B ≈3.6MB）——状态成本
≈8~9MB，与论文目标 7~9MB 同量级。**任何"正确"的通用设计都以吃掉全部收益
为代价**，设计空间整体判负，无需第四个设计。

## 3. 判例（入库）

1. **共享准入窗口死于窗口转速**：并发首见洪峰下按"共享预算"的通用串池三设计
   （先到先得/计数草图/精确窗口）分别死于冻结于垃圾、碰撞误收+饱和退化、
   窗口轮转快于跨源复发。单测（洪泛零误收）证明不了生产流量下的准入有效性
   ——必须在真实并发混合流量下逐值普查。
2. **算术闭包先于下一个设计**：当"使其有效"所需状态规模 ≈ 可回收规模时，
   设计空间整体判负，停止迭代设计、转入拆账（本轮 8~9MB 状态 vs 7~9MB 目标）。
3. **普查逐值计数是规范化收益的直接证据面**：实例总数差分受区块配对混淆，
   而逐值计数（Name/has_the_recipe/north 若池命中必为 ×1）不受混淆；v1 与 v3
   的 −22~23k 总回收在两腿统计等效，但逐值证明两者回收的都是边缘种群而非
   论文目标。
4. **单腿异常先复跑再归因**（批85 判例重演）：首腿 B 区块 −28%/终点 ×0.75
   收缩，第二论曾疑为 v3 热路径开销，复跑配对（6,154/6,092）证为环境噪声
   插曲——性能归因以复现为准。
5. **可达面拆账**：普查冗余 ≠ 反序列化可达冗余。boot 常量（DFU schema/反射：
   `<init>` ×2,355、`lambda$static$0` ×1,108、`minecraft` ×7,610，引用面为
   Schema/NamedType）非反序列化产物不可达；方块状态属性值在 worldgen 热路径；
   join-only 判据键 41,724 中冗余 ≈38.7k ≈2.2MB（0.25%）低于行动线。
6. **paperweight 直接文件机制**：内仓 reset 触发 `0001-paper-File-Patches`
   合成补丁（PaperHooks.java 独立化）——补丁序列重生成后的等价性以"逐 hunk
   对比 + 全量重放 + counts"三证收口，不接受文件名序号表面的连续性。

## 4. 账面

- 论文目标 7~9MB：通用设计可达 0（三设计实测），有效设计需状态 ≈8~9MB（净零）。
- 边缘回收（v1/v3 实测各 ≈1MB）：低于行动线且带共享池语义面，不落地。
- join-only 判据键 ≈2.2MB（0.25%）：低于行动线（最小已落地收益 0.81%、零语义面；
   批144 曾否决 1.8%）。
- String 规范化角度**关闭**；批次146 后堆画像回到批次145 收束态（866~868MB
  配对基线，0.84.0）。
