## 收割（补丁 0282）

`papoReadUtf` 重写为**零分配读**（镜像既有 papoWriteUtf 的 scratch 模式）：

1. **线程局部读 scratch**（初值 8KB，按需倍增至覆盖最长 65,535 串）：`readFully` 直读
   scratch，消每次 `byte[]`。
2. **短 ASCII 串有界去重缓存**（≤48B；4,096 槽直接映射、碰撞替换、entry 自持字节副本）：
   NBT 键与 id 类值词汇表极小且海量重复——重复读返回**同一不可变 String 实例**。
   语义恒等：String 不可变，NBT 全程按 equals/hashCode 比较；写入侧 papoWriteUtf 按
   值编码字节恒等。
3. 非 ASCII 回退：scratch 原位前缀移位（同数组 arraycopy 规范定义为经临时缓冲）+
   JDK 解码器，消 prefixed 副本。
4. 发布安全：entry 终态字段（JMM final-field freeze），读者见 null/旧 entry/新完整
   entry 三者之一。对抗面：固定尺寸无增长；>48B 旁路。

**实现勘误（自查捕获）**：去重比较必须用区间 `Arrays.equals(cached,0,len,scratch,0,len)`
——全数组比较在 scratch 增长后因长度不等永假、缓存永不命中。

## 判例

1. **读侧物化三重奏**：scratch（消载体）+去重（消重复值）+原位前缀（消回退副本）——
   与 R29 的物化-需求差范式互补，适用于一切"读入-立即消费"管线。
2. **不可变值共享是零语义面收割**：唯一前提是确认无身份依赖（==/IdentityHashMap/
   同步锁）——String 值域共享前已逐点审计。
3. 有界缓存必须**自证三性质**：定尺寸（对抗内容不可增长）、入口门（长度/类型）、
   发布安全（final-field 或锁）。

内存账（盘载窗）：papoReadUtf 面 −97.9%（83.5→2.0MB）；驻留 String/[B 小幅净降；
缓存固定 ≤0.5MB。版本 0.96.0。
