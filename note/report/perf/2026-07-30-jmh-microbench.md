## 解读

### 显著收益

- **0068（NBT 数组批量读）**：收益最大，5.9×–13.5×。逐元素 `readInt/readLong` 每个元素
  4/8 次带边界检查的单字节读 + 移位拼接；批量 `readFully` + `ByteBuffer` 大端视图解码
  把每元素成本压到一次内存拷贝级别。区块高度图（long[37]/section）、生物群系等
  在区块加载期密集触发，是最有端到端价值的一项。
- **0040/0047（fastIterator）**：2.6×–3.5×，且规模越大优势越大（省掉每键第二次
  哈希查找）。NBT 写出/合并是区块保存期热点。
- **0069/0070/0048**：2.1×–3.3×，均为每 tick / 每命令的高频小分配消除，绝对值小但
  调用频率高（每个有 Brain/LookControl 的生物每 tick）。

### 持平与代价（如实记录）

- **0067（NBT 字符串 ASCII 快速路径）**：ASCII 场景仅 ~1% 优势（JDK `readUTF` 的
  per-stream scratch 复用 + 内在化解码已相当快）；非 ASCII 场景因"扫描 + 回退重解码"
  慢 ~61%。NBT 键名与绝大多数值为 ASCII（资源名、UUID、JSON 文本骨架），玩家自定义
  文本（告示牌、书名）可能命中回退路径。综合仍为净收益，但收益主要来自分配次数减少
  （省 readUTF 内部 char[] 状态机），而非解码速度本身。
- **0045/0058（Vec3 分配消除）**：微基准中持平——JIT 逃逸分析在简单循环内把
  `new Vec3` 标量化了，分配本就不发生。真实服务器深调用栈中逃逸分析经常失效，
  该优化的价值是**消除对 EA 的依赖**（保证零分配），而非可测的时延差。

## 方法学声明

- 微基准验证"优化方向正确、量级可信"，不直接等于端到端 TPS；端到端收益 = 单点加速 ×
  该路径在真实负载中的时间占比。
- before/after 共享同一 JVM 配置与输入数据；分配敏感的用例在真实高 GC 压力场景下
  收益通常大于微基准所示。
